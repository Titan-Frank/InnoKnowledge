# World Knowledge Architecture V1.3

状态：当前代码和数据库正在执行的工程架构。

顶层概念标准是 `ai-nks-v0.2`，见 `docs/ai-nks-v0.2.md`。本文只解释 `world-v1.3` 怎样把统一知识对象、学科语义、课程投影、关系网络、桥接路径和证据治理落到可执行结构中。

## 一、结构总览

```text
来源与证据
  ↓
统一知识对象
  ├─ 学科语义画像
  ├─ 课程与教学投影
  └─ 结构化卡片与知识正文
  ↓
正式关系网络
  ├─ 学科内部关系
  ├─ 跨学科正式关系
  └─ 经显式桥接对象形成的路径

暂存、候选、审核、版本和质量治理横跨全部结构。
```

核心不是把所有学科塞进一张分类树，而是共享知识身份和关系语义，同时允许每个学科维护自己的角色系统。

## 二、统一知识对象

正式身份保存在 `world_nodes`。

九类顶层知识形态：

```text
entity / concept / property / process / event / method / rule /
representation / resource
```

它们回答“对象在最一般层面是什么”，不回答“它在数学中是定理还是定义”“它在八年级是核心还是支撑”。后两类问题由独立投影回答。

`properties_json.semantic_core` 可保存核心命题、形式表达、成立条件、适用边界、反例和常见误解。短定义仍保存在 `definition`。

### 桥接对象

桥接对象是普通 `world_nodes` 记录。以下条件可以表明桥接作用：

- `scope = universal`；
- 同时具有多个学科画像；
- `properties_json.bridge_role` 为语义桥、方法桥或类比桥。

桥接标签只用于候选召回。正式跨学科路径必须通过实际桥接对象和正式关系表达。

## 三、学科语义画像

`world_domain_schemas` 定义学科模式及允许角色，例如：

- 数学：定义、定理、证明方法、数学模型、解题方法、形式化表征；
- 物理：定律、原理、模型、现象、实验、测量方法、物理量；
- 计算机科学：算法、数据结构、计算模型、系统、程序构造、方法、理论；
- 化学：物质、反应、定律、模型、原理、实验、分析方法、化学性质；
- 生物学：结构、过程、机制、理论、模型、实验、分类、生物体。

`world_domain_profiles` 把一个知识对象投影到某个学科模式，保存：

- 学科；
- 模式编号和版本；
- 学科角色；
- 学科特有属性；
- 来源证据和治理状态。

学科画像不保存课程、学段、年级、课程角色或教学画像。

## 四、课程与教学投影

`world_curriculum_projections` 把同一个知识对象投影到具体教学编排，保存：

- 课程体系；
- 学科；
- 学段和年级；
- 核心、支撑、首次引入、巩固、迁移、评价等课程角色；
- `properties_json.pedagogical_profile` 教学画像；
- 来源证据、状态和审核信息。

这层分离保证教材顺序和教学策略不会改变知识对象身份或学科本体语义。

## 五、正式关系网络

`world_edges` 是唯一正式关系表。当前关系以中文为主表达：

```text
是一种、是实例、是组成部分、包含、具有属性、使用、产生、依赖、
是前置知识、导致、影响、表示、形式化表达、应用于、类似于、
建模描述、主题是、相关
```

数据库保存稳定内部代码，接口附带中文名称。完整映射见 `packages/types/src/relations.ts`。

同一对象不是关系。身份确认后执行节点归一，不能创建 `same_as`。

### 跨学科查询

正式跨学科关系仍写入 `world_edges`。`world_cross_domain_edges` 根据关系两端的学科画像推导，只用于查询和统计，不构成第二份事实存储。

## 六、受控分类与标签

`world_taxonomy_terms` 和 `world_taxonomy_edges` 负责受控分类。标签只适合：

- 检索；
- 聚类；
- 候选召回；
- 临时组织。

标签不能承担：

- 顶层知识形态；
- 学科角色；
- 正式事实关系；
- 关系证据。

如果一个标签长期决定系统行为，应把它升级为受控分类、学科角色或正式关系。

## 七、证据与来源策略

`world_source_policies` 管理教材、学术论文、百科资料、课程标准、结构化数据库和专家知识的证据资格、可信等级和审核要求。

证据相关对象：

- `world_mentions`：来源中对知识对象的提及；
- `world_evidence`：可核验片段、图片、表格或公式；
- `world_evidence_links`：证据与对象、关系、画像、投影等记录的补充链接；
- `source_fragments`：由服务端聚合的来源片段视图。

证据平面回答：

- 为什么存在这个对象？
- 为什么成立这条关系？
- 学科角色和课程投影来自哪里？
- 正文中的结论能否回到来源？

编号归属校验不能替代语义蕴含判断。

## 八、跨学科治理

跨学科发现是治理流程，不是第五种事实层。

`world_interdisciplinary_candidates` 保存：

- 同一对象候选；
- 直接关系候选；
- “来源对象—桥接对象—目标对象”桥接路径候选。

名称、别名、语义键、主题标签和匹配分数只用于发现。直接关系必须选择合格证据；桥接路径两段必须分别选择关系、方向和属于本段的直接证据。批准后仍需独立应用步骤，才会归并节点或写入 `world_edges`。

## 九、生产写入边界

课时工作器只能写：

- `world_lesson_runs`；
- `world_staging_*`。

正式 `world_*` 的对象、关系、学科画像、课程投影、卡片、正文、身份归一、编号重映射和最终质量状态只能由归并、规范化和受锁保护的治理步骤写入。

`world_staging_domain_profiles` 和 `world_staging_curriculum_projections` 分开保存，保证课时抽取阶段也不混淆学科语义和教学位置。

## 十、公共消费视图

服务端按对象编号组装 `ApiUnit`：

```text
node
relations
domain_profiles
curriculum_projections
mentions
evidence
media
source_fragments
card
body
completeness
```

查看器、检索和生成系统应消费 `ApiUnit`，不自行拼出另一套隐含契约。

## 十一、结构规则与扩展规则

1. 新学科增加独立领域模式，不扩大全学科共享角色枚举。
2. 新关系先进入统一关系目录、中文定义、机器结构和测试。
3. 新来源先定义来源策略，再实现采集器。
4. 跨学科专用统计使用派生视图，不复制正式事实。
5. 身份冲突通过节点归一解决。
6. 教材、课程标准和考点只形成来源、边界、投影或评价任务，不直接定义对象身份。
