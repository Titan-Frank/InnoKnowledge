# Security policy

[中文说明](SECURITY.zh-CN.md)

## Reporting a vulnerability

Do not disclose exploitable details, credentials, personal information, private learning material, or unauthorized derived data in a public issue or discussion.

If GitHub private vulnerability reporting is enabled, use **Security → Report a vulnerability**. If it is not enabled, open a public issue containing only a high-level description of the affected component and a request for a private contact channel. Do not attach the exploit, secrets, logs, source material, or real records.

A useful private report includes the affected version, risk, safe reproduction steps, and suggested mitigation. Use synthetic fixtures wherever possible and allow the maintainer time to investigate before public disclosure.

## Exposed credentials or data

Immediately revoke and rotate any credential that entered a commit, log, screenshot, or attachment. Removing the file or commit is not sufficient because copies may remain in history, caches, or forks.

If private textbooks, personal information, learner records, or institution data were uploaded, stop further distribution and report the affected scope and containment steps through the private channel.
