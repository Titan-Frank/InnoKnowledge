# AI-NKS v0.2：人工智能原生多学科知识网络标准

更新日期：2026-07-13

状态：当前顶层概念标准。

本文冻结 Open Knowledge Map 的多学科知识模型。它定义系统中的知识身份、学科语义、课程投影、跨学科桥接、来源证据和运行时边界。对应的可执行工程结构是 `world-v1.3`，公共消费契约是 `ApiUnit`。

## 一、定位

Open Knowledge Map 的目标不是构建一张平面的“多学科知识图谱”，而是构建一套可供人工智能检索、推理、教学和科研辅助使用的多学科知识网络。

> AI-NKS v0.2 以统一知识对象为身份核心，以学科语义画像解释对象在不同学科中的角色，以课程投影表达教学位置，以显式桥接对象连接不同学科，并以来源证据、人工审核和版本治理约束正式写入。

版本边界如下：

| 名称 | 层级 | 作用 |
|---|---|---|
| `ai-nks-v0.2` | 顶层概念标准 | 定义知识系统的对象、投影、网络、运行时和治理边界 |
| `world-v1.3` | 可执行工程结构 | 定义 PostgreSQL 表、机器可读结构、关系代码和质量约束 |
| `ApiUnit` | 公共消费契约 | 聚合一个知识对象及其关系、学科语义、课程投影、证据和正文 |

三个名称不能混用。概念标准决定“系统是什么”，工程结构决定“数据怎样存”，公共契约决定“下游怎样读”。

## 二、核心原则

1. **知识对象具有统一身份。** 同一个知识对象不能因为出现在多个教材、课程或学科中就复制多个正式身份。
2. **学科语义与课程教学分离。** 学科角色描述对象在一个学科里是什么；课程投影描述它在哪个课程、学段和年级中怎样被使用和教学。
3. **教材不定义知识本体。** 教材是来源证据和教学路径，章节、目录、课标条目和考点不是默认知识对象。
4. **跨学科连接必须可解释。** 不用一条含义模糊的边把不同层次的对象直接连起来；优先通过变化率、优化、选择机制等显式桥接对象形成路径。
5. **同一身份通过归并解决。** 已停用的 `same_as` 不得新建；确认是同一对象时必须执行节点归一。
6. **候选不等于事实。** 名称、别名、主题标签和向量相似度只能用于发现候选，不能替代直接证据和人工审核。
7. **中文是关系的主表达。** 界面、提示词和文档使用中文关系名称；稳定代码只在存储、接口和程序内部使用。

## 三、总体结构

```text
来源材料
  ├─ 教材、课程标准、论文、百科、数据库、专家知识
  ↓
统一知识对象
  ├─ 唯一身份、短定义、语义核心、证据
  ├─ 学科语义画像
  └─ 课程与教学投影
  ↓
多学科知识网络
  ├─ 学科内部关系
  ├─ 显式桥接对象
  └─ 受治理的跨学科关系与路径
  ↓
知识运行时
  ├─ 对象级检索、关系路径、带依据生成
  └─ 智能辅导、科研辅助和知识发现

来源策略、证据、人工审核、版本和质量治理贯穿全部层级。
```

这不是一棵统一分类树。不同学科保留自己的角色系统，跨学科连接由共享的知识身份、受控关系和桥接对象完成。

## 四、统一知识对象

知识对象是正式网络的身份单位，对应 `world_nodes`。它至少包含：

| 维度 | 含义 | 工程落点 |
|---|---|---|
| 身份 | 编号、名称、别名、状态 | `world_nodes` |
| 顶层形态 | 实体、概念、属性、过程、事件、方法、规则、表征、资源 | `world_nodes.kind` |
| 定义与语义核心 | 短定义、核心命题、公式、条件、边界、反例、误解 | `world_nodes.definition`、`properties_json.semantic_core` |
| 适用范围 | 通用、学科特定或文化特定 | `world_nodes.scope` |
| 桥接角色 | 语义桥、方法桥或类比桥 | `world_nodes.properties_json.bridge_role` |
| 来源证据 | 对象为何存在、怎样被描述 | `world_mentions`、`world_evidence` |
| 阅读正文 | 面向人和生成系统的连续说明 | `world_node_bodies` |

一个对象可以属于多个学科，但仍只有一个正式身份。例如“导数”可以同时具有数学学科画像和物理学科画像，而不需要创建“数学导数”和“物理导数”两个节点。

## 五、学科语义画像

学科语义画像对应 `world_domain_profiles`，回答：

> 这个知识对象在某个学科中扮演什么角色？

统一结构只有以下公共字段：

- 学科；
- 学科模式编号和版本；
- 学科角色；
- 学科特有属性；
- 来源证据和治理状态。

不同学科不共享一套僵硬的角色枚举：

| 学科 | 角色示例 |
|---|---|
| 数学 | 定义、定理、证明方法、数学模型、解题方法、形式化表征 |
| 物理 | 定律、原理、模型、现象、实验、测量方法、物理量 |
| 计算机科学 | 算法、数据结构、计算模型、系统、程序构造、方法、理论 |
| 化学 | 物质、反应、定律、模型、原理、实验、分析方法、化学性质 |
| 生物学 | 结构、过程、机制、理论、模型、实验、分类、生物体 |

具体角色由 `world_domain_schemas` 和 `schemas/world-domain-schema.schema.json` 管理。学科画像中不得写入学段、年级、课程角色或教学画像。

## 六、课程与教学投影

课程投影对应 `world_curriculum_projections`，回答：

> 同一个知识对象在某个课程、学段和年级中处于什么教学位置？

课程投影包含：

- 课程体系编号；
- 学科；
- 学段和年级范围；
- 核心、支撑、首次引入、巩固、迁移、评价等课程角色；
- 学习目标、难度、诊断问题、常见错误、评价任务、补救和拓展建议；
- 生成模型、提示词版本、输入指纹、置信度、审核状态和证据编号。

同一对象可以拥有多个课程投影。教材章节只影响这些投影和教学路径，不改变对象的统一身份和学科本体语义。

## 七、中文关系体系

`world-v1.3` 使用 18 类正式关系。中文名称是人和模型的主表达，括号内代码是内部稳定标识。

| 中文关系 | 内部代码 | 方向 | 语义 |
|---|---|---|---|
| 是一种 | `is_a` | 有向 | 具体类型属于更一般的类型 |
| 是实例 | `instance_of` | 有向 | 具体对象是一般对象的实例 |
| 是组成部分 | `part_of` | 有向 | 来源对象构成目标对象的一部分 |
| 包含 | `contains` | 有向 | 来源对象在结构上包含目标对象 |
| 具有属性 | `has_property` | 有向 | 对象具有某种性质或可测特征 |
| 使用 | `uses` | 有向 | 方法、模型或过程使用目标对象 |
| 产生 | `produces` | 有向 | 过程、机制或方法产生目标对象 |
| 依赖 | `depends_on` | 有向 | 来源对象成立、运行或理解时依赖目标对象 |
| 是前置知识 | `prerequisite_for` | 有向 | 来源对象应先于目标对象学习 |
| 导致 | `causes` | 有向 | 来源对象对目标对象具有直接因果作用 |
| 影响 | `affects` | 有向 | 来源对象改变目标对象，但不声称充分因果 |
| 表示 | `represents` | 有向 | 符号、图式或表达形式指向目标对象 |
| 形式化表达 | `formalizes` | 有向 | 来源对象为目标对象提供数学、逻辑或符号形式 |
| 应用于 | `applies_to` | 有向 | 方法、理论或工具可用于目标问题或领域 |
| 类似于 | `analogous_to` | 无向 | 两个对象在明确机制或结构框架下可解释类比 |
| 建模描述 | `models` | 有向 | 来源模型对目标对象、过程或现象进行建模 |
| 主题是 | `about` | 有向 | 资源、表征或内容以目标对象为主题 |
| 相关 | `related_to` | 无向 | 存在稳定但尚未细化的关联 |

关系代码由 `packages/types/src/relations.ts` 统一维护。任何界面、提示词或文档不得另建一份含义不一致的关系表。

## 八、显式桥接对象与跨学科路径

桥接对象也是普通知识对象，不是隐藏标签或特殊边。它通过通用范围、多学科归属或 `bridge_role` 表明桥接作用。

例如：

```text
导数 ──形式化表达──> 变化率 ──应用于──> 速度

自然选择 ──形式化表达──> 选择机制 ──类似于── 遗传算法
```

每条桥接路径必须满足：

1. 恰好包含“来源对象—桥接对象—目标对象”两段；
2. 桥接对象已经是正式知识对象；
3. 两段分别选择关系类型、方向和直接证据；
4. 每条证据必须属于它支持的那一段，不能借用另一段证据；
5. 人工批准后仍需执行独立应用步骤，才会写入正式关系表；
6. 正式关系统一写入 `world_edges`，不复制一张跨学科关系表。

`world_cross_domain_edges` 只是从正式关系和对象学科画像推导出的只读视图。

## 九、来源与证据治理

来源不是只有教材。当前来源策略表定义教材、学术论文、百科资料、课程标准、结构化数据库和专家知识六类来源，并规定可信等级、是否允许支持关系、是否需要额外人工确认。

来源策略与具体采集器是两个层次：

- `world_source_policies` 规定已入库证据怎样被治理；
- 当前自动抽取主流程仍以教材为主；
- 未来论文、百科或数据库采集器必须进入同一证据和归并流程，不能绕过质量检查直接写正式网络。

证据编号属于当前上下文，只能证明“引用存在”，不能自动证明结论被语义蕴含。正式研究结论仍需要独立的语义核验和人工裁决。

## 十、跨学科治理流程

跨学科扫描产生三类候选：

1. **同一对象候选：** 两个节点可能是同一身份；批准后执行节点归一。
2. **直接关系候选：** 两个不同学科对象可能存在一条稳定关系。
3. **桥接路径候选：** 两个对象可通过一个显式桥接对象形成两段可解释路径。

扫描只写 `world_interdisciplinary_runs` 和 `world_interdisciplinary_candidates`。待审核、已批准、已拒绝和已应用是明确的治理状态。课时工作器不得直接写这些候选对应的正式节点或关系。

## 十一、知识单元与运行时

`ApiUnit` 是一个知识对象的消费视图，而不是生产阶段的中间文件。它聚合：

- 对象身份和语义核心；
- 入边和出边；
- 学科语义画像；
- 课程与教学投影；
- 提及、证据、媒体和来源片段；
- 结构化卡片和知识正文；
- 完整度信号。

知识运行时当前支持对象级文本、向量和混合检索，以及带证据编号归属校验的同步和流式生成。后续运行时应围绕知识对象和关系路径完成教学规划、跨领域解释、科研辅助和知识发现，而不是只拼接文档片段。

## 十二、生产与写入边界

```text
教材 PDF 或 Markdown
  → 课时级对象、关系、学科画像和课程投影抽取
  → world_staging_* 暂存
  → 归并、身份归一和正式 world_* 写入
  → 正文与教学画像生成
  → 跨学科候选扫描、人工复核和独立应用
  → 严格质检、图完整性检查和 ApiUnit 聚合
```

课时工作器只能写 `world_lesson_runs` 和 `world_staging_*`。正式对象、关系、画像、投影、重复项归并、编号重映射和最终质量状态只能由归并器、规范化阶段和受锁保护的应用步骤负责。

## 十三、当前实现边界

已经实现：

- `world-v1.3` 数据库迁移和机器可读结构；
- 统一关系目录、中文名称和中文输入归一化；
- 六套领域模式与领域角色校验；
- 学科画像和课程投影分离；
- 六类来源策略；
- 同一对象、直接关系和显式桥接路径候选；
- 逐段证据审核、身份归一和正式关系应用；
- `ApiUnit`、对象级检索、带依据生成和查看器工作台。

尚未证明或尚未完成：

- 论文、百科、数据库和专家知识的完整自动采集器；
- 多学科大规模人工金标准和跨学科关系召回率；
- 自动生成结论的独立语义蕴含验证；
- 基于关系路径的完整教学规划器和科研代理；
- 对真实学习效果和科研效率的因果改进。

## 十四、演化规则

1. 新关系先进入统一关系目录、中文定义、机器结构和测试，再允许写入正式数据。
2. 新学科优先新增独立领域模式，不扩大全学科共享角色枚举。
3. 新来源先定义来源策略，再实现采集器和证据适配。
4. 身份问题通过归并解决，不新增“同一对象”关系。
5. 跨学科专用查询优先使用派生视图，不复制正式关系表。
6. 概念标准、共享类型、数据库、流水线、接口、查看器、文档和技术报告必须在同一次升级中保持一致。
