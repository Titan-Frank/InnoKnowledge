我会把它当成产品信息架构和 AI-NKS 对象模型问题来想：知识点详情页要同时服务学习者理解、教师审核、AI Runtime 调用和证据治理。

我觉得一个知识点点进去后，不应该只是“定义 + 原文 + 关系图”，而应该是一个 Knowledge Unit / Knowledge Object 的驾驶舱。

新的知识体系里，一个知识点至少有三种使用者：学习者要“学懂它”，教师要“判断能不能教、怎么教”，AI Runtime 要“稳定调用它”。AI-NKS 的定义本身也强调知识对象要同时具备语义核心、教学属性、计算接口、证据来源和版本治理，并通过 Runtime 支持检索、组合、推理、解释、工具调用和反馈更新。 当前 OKM 分支里的 ApiUnit 也已经把一个知识点定义成由 node、关系、领域画像、mentions、evidence、media、source fragments、card、body 聚合出来的完整视图，而不是单个节点。

所以详情页的核心原则应该是：

点进去之后，用户看到的不是一个“点”，而是这个知识对象的身份、语义、来源、关系、教学用法、AI 调用方式和演化状态。

1. 第一屏：先让人一眼知道“这是什么”

第一屏应该极其清楚，不能一打开就是一大堆表和 JSON。

建议顶部显示：

知识点名称：电场强度
类型：concept / property / rule / method / representation ...
一句话定义：描述电场强弱和方向的物理量
所属领域：高中物理 / 电磁学
学习层级：概念理解 / 公式应用
状态：active / reviewed / draft
可信度：0.92
证据数量：5
关系数量：12
正文状态：已生成 / 待生成 / 人工维护

这里对应当前工程中的 world_nodes 和 ApiUnit.node。在 OKM 当前契约里，node 是知识对象骨架，包含 id、name、kind、definition、domains、status 等字段。

这一屏的目的不是展示全部内容，而是回答四个最基本的问题：

它叫什么？
它是什么类型？
它的最短定义是什么？
它是否可信、可用、可追溯？
2. 核心正文：给学习者看的“可读解释”

第二块应该是 知识正文，也就是当前分支里的 world_node_bodies / ApiUnit.body。

这部分不是教材原文，也不是卡片拼接，而是面向学习者和 AI 生成系统的连续解释。当前知识单元契约已经明确：body 是持久化知识正文，课本原文来自 source_fragments，结构化摘要来自 card，三者不能混。

正文建议结构：

## 直观解释
用自然语言解释这个知识点解决什么问题。

## 正式定义
给出标准定义，必要时有公式。

## 核心本质
解释它背后的第一性原理或关键机制。

## 成立条件
什么时候成立，什么时候不成立。

## 例子
一个典型教材例子或真实应用。

## 易错点
学生最容易误解的地方。

## 小结
用 2–3 句话收束。

比如“电场强度”的正文不能只写“E=F/q”，还应该说明：

它不是某个试探电荷自己的性质，而是电场在空间中某一点的性质；
它通过单位正电荷受力来定义；
公式 E = F/q 在教材语境下有适用前提；
方向通常规定为正电荷受力方向。

这部分是详情页最重要的“阅读层”。

3. Semantic Core：稳定的知识骨架

正文是给人看的，Semantic Core 是给人和 AI 都能稳定调用的。

这里应该显示：

定义 definition
核心命题 core_claims
公式 / 符号 formal_expressions
成立条件 conditions
适用范围 scope
边界 conditions / boundaries
反例 counterexamples
常见误解 misconceptions

AI-NKS v0.2 中把 Semantic Core 定义为知识对象的语义核心，包含定义、核心命题、公式、前提条件、适用范围、边界条件、反例和常见误解。 当前 OKM 的 ai-nks-v0.1 也把 Knowledge Object 的语义核心落在 world_nodes.properties.semantic_core，并把正文、证据、教学画像等作为更完整的对象视图组成部分。

UI 上不一定要叫 “Semantic Core”，可以叫：

知识骨架

建议以结构化方式展示：

核心命题
- 电场强度描述电场在某点的强弱和方向。
- 电场强度由试探电荷所受电场力与电荷量之比定义。

公式
- E = F / q

成立条件
- 用正试探电荷定义方向。
- 试探电荷应足够小，不显著改变原电场。

边界
- 不应把 E 理解为试探电荷自身属性。

这一块对 AI Tutor 特别重要，因为 Runtime 生成解释时应优先使用这些稳定结构，而不是只读长正文。

4. Knowledge Network：它在知识网络中的位置

知识点详情页必须显示关系，但不能只是画一个大图。应该把关系按意义分组，让用户知道“学它之前需要什么，学它之后能通向什么，它和谁相似、谁冲突、哪里应用”。

AI-NKS 报告中至少区分了语义关系、学习关系、证据关系、应用关系和演化关系；其中语义关系包括 is-a / part-of / same-as / related-to / contradicts，学习关系包括 prerequisite / successor / remediate-by，应用关系包括 applies-to / used-in / solves / requires-tool。

详情页可以显示成五组：

前置知识
- 电荷
- 电场
- 力
- 比值定义

组成 / 结构关系
- 电场强度 part_of 电场描述体系
- 电场力 related_to 电场强度

后续知识
- 电势
- 匀强电场
- 电场线
- 带电粒子在电场中的运动

应用场景
- 判断电场强弱
- 分析带电粒子受力
- 解释电场线疏密

跨学科 / 类比
- 重力场强度
- 温度场中的空间分布

图谱区域可以有，但应该是辅助。推荐交互方式：

默认显示一跳核心邻居
可以切换：学习路径 / 结构关系 / 应用关系 / 跨学科关系
点击关系边可以查看证据

这比“所有节点铺开”更适合学习。

5. Evidence：这个知识从哪里来

新的知识体系必须把证据做成一等公民。否则它只是一个漂亮的 AI 生成知识库。

详情页应该有一个非常明确的“证据”区域：

教材原文
- 来源教材
- 页码 / 章节 / anchor
- 原文片段
- 对应支持的声明

图片 / 表格 / 公式证据
- 图片
- 图注
- 所属段落
- VLM 判断结果：核心图 / 辅助图 / 待复核 / 已拒绝

证据覆盖
- 定义由哪些 evidence 支持
- 公式由哪些 evidence 支持
- 关系由哪些 evidence 支持
- 易错点由哪些 evidence 支持

当前 OKM 的 ApiUnit 已经把 evidence、media、source_fragments 分开：evidence 支撑知识对象存在和解释，media 从图片证据解析，source_fragments 是课本原文片段。

UI 上我建议这样做：

正文里的每个关键句子可以有 [1] [2] 角标
点击角标，右侧展开对应 evidence
证据区可以反向显示：这条证据支撑了哪些声明 / 关系 / 卡片字段

这样教师或审核者可以快速判断：这个知识点到底是“有证据的知识”，还是“模型补出来的解释”。

6. 多版本表达：同一个知识点的不同 Realization

新的知识体系里，教材不应该是知识的唯一形态，而是 Knowledge Realization 的一种。AI-NKS 文档里也明确区分 Knowledge Object、Knowledge Skeleton、Knowledge Realization 和 Knowledge Network：Object 是管理单元，Skeleton 是稳定语义核心，Realization 是面向特定学习者、任务、语言和媒介的表达实例。

所以详情页应该有一个“表达版本”区：

当前表达
- 教材解释版
- Tutor 对话版
- 教师备课版
- 初学者直观版
- 进阶推导版
- 例题解析版
- 项目应用版

比如“牛顿第二定律”可以有：

初中版：力会改变物体运动状态
高中版：F = ma，合外力决定加速度
大学版：动量形式 F = dp/dt
工程版：用于机器人控制和车辆动力学
AI Tutor 版：一步步追问质量、力、加速度
仿真实验版：拖动质量和力，观察加速度变化

这和 AI-NKS 报告中“同一个 Knowledge Object 可以生成高中版、大学版、工程应用版、AI Tutor 对话版、仿真实验版和评价任务版”的思路一致。

在 OKM 现阶段，至少可以先做两个 Realization：

教材解释版：body
Tutor 解释版：由 Runtime 临时生成，但保留 used_units 和 evidence
7. 教学画像：它应该怎么被教、怎么被学

一个知识点详情页如果只展示知识本身，就还是传统知识库。新的知识体系必须展示“教学属性”。

建议有一块叫：

学习与教学

内容包括：

学习目标
- 学生能说出……
- 学生能解释……
- 学生能应用……

认知层级
- 记忆 / 理解 / 应用 / 分析 / 创造

难度
- basic / intermediate / advanced

前置诊断
- 学这个之前先问学生什么问题？

常见错误
- 把 E 理解为试探电荷自己的性质
- 把电场线当作真实存在的线

补救建议
- 回到“力”和“比值定义”
- 用重力场强度做类比

拓展建议
- 连接到电势、电场线、带电粒子运动

AI-NKS 的 Pedagogical Profile 就包含学习目标、认知层级、难度、推荐学习对象、前置诊断问题、常见错误、例题、练习、补救建议和拓展建议。 当前 OKM 也建议把教学画像放在 world_domain_profiles.properties.pedagogical_profile，因为同一知识对象在不同学科、学段里可能有不同教学重点。

这里有一个重要设计：教学画像不要塞进 node 本体。

比如“能量”这个知识对象，在初中物理、高中物理、化学、生物里的教学重点不同，所以教学画像应该是 domain profile，而不是改写“能量”这个对象本身。

8. 练习与评价：点进去后应该能立刻测一测

详情页应该不仅能“看”，还要能“评估掌握”。

建议显示：

诊断题
- 你认为电场强度是否取决于试探电荷大小？为什么？

基础题
- 根据 F 和 q 计算 E

概念辨析题
- 电场强度大，是否说明试探电荷受力一定大？

应用题
- 比较两个点的电场强弱

迁移题
- 类比重力场强度解释电场强度

评分 Rubric
- 正确提到比值定义
- 正确区分电场属性和试探电荷属性
- 正确说明方向

AI-NKS 文档中提到知识驱动评价应绑定目标 Knowledge Object、学习目标、认知层级、评分标准、常见错误模式和反馈建议，而且评价不只是判断对错，还要诊断学习者在哪些知识对象或关系上存在缺口。

这块对未来 AI Tutor 很关键，因为它可以直接支持：

解释 → 诊断 → 反馈 → 补救路径
9. AI Runtime 区：这个知识点如何被 AI 调用

这块可以默认折叠，但必须存在。因为新的知识体系不是只给人看的，它还要给 AI Runtime 用。

建议显示：

AI 可调用摘要
- retrieval_text
- compact_context
- allowed_claims
- source_refs
- relation_hints

工具绑定
- calculator
- physics_simulator
- python
- graph query
- visualization

Runtime 用法
- 可用于 explain_concept
- 可用于 solve_problem
- 可用于 diagnose_misconception
- 可用于 generate_assessment

生成约束
- 回答时必须引用 evidence
- 不得超出适用范围
- 若用户缺少前置知识，先解释 prerequisite

AI-NKS 的 Runtime 不是只做文本检索，它需要进行对象级检索、知识组合、推理、工具调用和 grounded generation；检索结果还应包含对象 ID、版本、来源、置信度和适用条件。 Grounded Generation 也要求回答绑定使用了哪些 Knowledge Object、来源和版本、关键推理步骤，并区分事实、教学类比、推测或建议。

这块可以给开发者、研究者和 AI Tutor 使用，不一定给普通学生默认展示。

10. 质量与治理：这个知识点是否可信、是否需要审核

详情页还应该显示质量状态，否则无法成为教育基础设施。

建议显示：

质量状态
- draft / active / reviewed / deprecated
- expert_reviewed: true / false
- reviewer
- confidence
- last_updated
- schema_version
- evidence_coverage
- relation_quality
- body_quality

风险提示
- 证据不足
- 关系待复核
- 图片待复核
- 可能存在跨教材命名冲突
- 可能存在争议或多种解释

版本记录
- v1.0 初次抽取
- v1.1 增加例题
- v1.2 修正边界条件

AI-NKS 的 Governance Metadata 包含来源证据、作者、审核者、生成方式、置信度、更新时间、版本差异、影响范围、风险标注和回滚记录。 它还强调高质量 AI-NKS 必须有人类专家参与审核，审核重点包括语义核心、关系、学习目标、常见误解、评价任务、来源证据和对齐关系。

这块对教师和系统维护者特别重要。

14. 一个具体例子：点开“电场强度”应该看到什么

可以想象页面是这样：

电场强度
concept / 高中物理 / 电磁学 / active / reviewed

一句话定义：
电场强度是描述电场在某点强弱和方向的物理量。

知识正文：
## 直观解释
电场看不见，但可以通过放入试探电荷后受到的力来判断某点电场的强弱……

## 正式定义
电场中某点的电场强度等于试探电荷所受电场力与其电荷量之比，E = F/q……

## 易错点
电场强度不是试探电荷自己的性质……

知识骨架：
- 核心命题：E 描述电场自身性质
- 公式：E = F/q
- 条件：试探电荷足够小
- 边界：不适合把 E 理解成某个电荷的受力大小

前置知识：
- 电荷
- 电场
- 电场力
- 比值定义

后续知识：
- 电场线
- 电势
- 匀强电场
- 带电粒子运动

应用：
- 比较不同点电场强弱
- 分析带电粒子受力
- 解释电场线疏密

证据：
[1] 教材第 X 页：……
[2] 图 X：电场线示意图……

诊断题：
如果把试探电荷 q 变成 2q，电场强度 E 会变吗？为什么？

AI Runtime：
- 可用于 explain_concept
- 可用于 solve_formula_problem
- 可用于 diagnose_misconception
- tool_binding: formula_calculator

这才是新知识体系里的“知识点”。

15. 最重要的产品判断

我认为详情页的设计重点不是“展示更多字段”，而是要体现一种新的知识观：

传统详情页：这个知识点在教材哪里？定义是什么？
新知识体系详情页：这个知识对象是什么？它为什么可信？它依赖什么？它能生成什么表达？它能支持什么学习任务？AI 如何调用它？它如何被审核和演化？

所以，最终可以浓缩成一句话：

一个知识点点进去后，应该同时是学习页、证据页、关系页、教学页、Runtime 页和治理页；只是根据用户身份显示不同层级。

好的，这是节点里面的结构。那退一步讲，到底什么应该被抽成知识节点呢？要参考课标吗？考点？教材目录？还是什么？如何保证知识的完整性、知识点的准确性。这个抽取的粒度应该怎么把控？

我会先把问题拆成：抽取来源、节点判定、粒度控制、完整性与准确性质量门。关键不是课标、考点、目录三选一，而是建立多来源约束和校准规则。

这里还要先定义“知识对象资格”：只有可维护、可调用、可教学、可评测的内容才应成节点，而不是简单把文本名词全抽出来。

我的判断是：知识节点既不应该直接等于课标条目，也不应该等于考点，也不应该等于教材目录；它应该是三者共同约束下，被抽象出来的“可独立引用、可解释、可验证、可复用、可运行”的 Knowledge Object。

换句话说：

课标决定：该不该进入学习范围
教材决定：它如何被表达、证据在哪里、学习顺序是什么
考点决定：它如何被评价、常见题型和易错点是什么
知识本体决定：它到底是不是一个稳定知识对象
AI Runtime 决定：它是否值得被单独调用和组合
1. 最核心原则：知识节点不是“文本块”，也不是“目录项”

AI-NKS 文档里有一句非常关键：传统教材里的“知识点”通常依附于章节结构，边界由教材作者决定；但对 AI 系统来说，边界不清会导致检索不稳定、解释不一致、来源不可追踪和跨教材对齐困难。因此 Knowledge Object 的目的，是把知识从教材章节中解耦出来，让它能被唯一标识、独立引用、版本管理、关系连接、教学适配和运行调用。

所以判断一个东西该不该成为知识节点，不能问：

教材里有没有出现？
目录里有没有写？
考试会不会考？
课标有没有列？

而应该问：

它是否是一个稳定的知识对象？
它是否能被定义？
它是否能和其他知识产生关系？
它是否有证据来源？
它是否能被学习、解释、评价或调用？

如果答案是肯定的，它才应该成为节点。

2. 课标、考点、教材目录分别应该扮演什么角色
2.1 课标：决定“范围”和“能力要求”，不是直接生成节点清单

课标很重要，但它不应该直接变成节点表。课标更多是 coverage boundary 和 learning objective source。

它回答：

这个阶段应该学到什么？
学到什么程度？
对应什么核心素养或能力？
哪些内容是必须覆盖的？
哪些内容是拓展性的？

例如课标里说“认识质量守恒定律，并能用其解释常见化学反应现象”。这里至少会导出几个东西：

Knowledge Object:
- 质量守恒定律
- 化学反应
- 反应物
- 生成物
- 质量
- 封闭体系 / 开放体系，视教材和学段而定

Skill Object:
- 用质量守恒定律解释实验现象
- 根据反应前后质量关系进行简单判断

Assessment / Task Object:
- 判断反应前后质量是否守恒
- 解释蜡烛燃烧质量变化的表观矛盾

Misconception Object:
- “反应后质量变小，所以质量不守恒”

课标本身不是节点，但课标会约束节点的必要性、学习阶段、掌握水平和评价边界。

2.2 教材：提供“证据、表达、顺序、例子”，不是最终本体

教材是最重要的证据来源，但教材目录不等于知识网络。AI-NKS 文档强调构建流程必须从来源进入 evidence anchoring：教材页码、段落 ID、视频时间戳、代码行号等证据锚点是可信性的基础；没有证据锚点，知识对象就会变成无法追溯的生成内容。

教材回答的是：

这个知识在当前教材中如何出现？
定义或例子怎么说？
它在哪一章、哪一节、哪一页？
它和哪些图、表、实验、公式一起出现？
教材安排的学习顺序是什么？

但教材目录经常有两类问题：

1. 目录粒度过粗：
   “物质的变化和性质”下面可能包含概念、现象、分类、实验方法、判断技能等多个对象。

2. 目录粒度过细或修辞化：
   “探究活动”“观察与思考”“你知道吗”“本节小结”不一定是知识对象。

所以教材目录更适合做 source structure 和 learning sequence hint，不能直接当知识节点。

2.3 考点：决定“评价权重和题型”，不是知识真理来源

考点很有用，但不能让考点主导知识本体。因为考点是评价系统对知识的采样，它天然会偏向可测、可标准化、可出题的内容。

考点回答：

哪些知识常被评价？
常见题型是什么？
易错点是什么？
掌握到什么程度？
哪些知识是高频迁移点？

它应该进入：

pedagogical_profile
assessment_tasks
common_errors
diagnostic_questions
exam_weight
task_templates

但不应该让“考不考”决定“有没有这个知识”。有些知识不高频考，但它是重要前置知识；有些考点其实是多个知识对象的组合任务，而不是单个节点。

例如“根据图像判断物体运动状态”是考点，但它不应该只抽成一个 concept 节点。它更像：

Task Object:
- 根据 s-t 图像判断运动状态

需要连接：
- 位移
- 时间
- 速度
- 匀速直线运动
- 图像斜率
- 坐标轴含义
- 图像解读技能
3. 什么应该被抽成知识节点

我建议 OKM 采用 六类对象 + 两类非对象 的判定法。AI-NKS 文档也建议教育场景采用多粒度策略，包括 Concept Object、Proposition Object、Procedure Object、Skill Object、Task Object、Misconception Object；粒度过粗会退化为文档 chunk，过细则会导致网络复杂、维护成本高、教学意义弱。

3.1 Concept Object：概念节点

抽取对象：

电场
电场强度
化学反应
溶液
质量
生态系统
变量
函数
算法

判定标准：

能被定义
能被举例
能和其他概念发生关系
在多个场景中复用

适合的关系：

is_a
part_of
has_property
related_to
prerequisite_for
3.2 Proposition / Rule Object：命题、定律、原理、公式节点

抽取对象：

质量守恒定律
牛顿第二定律
欧姆定律
能量守恒
光合作用释放氧气
三角形内角和为 180°

判定标准：

表达一个稳定判断、规律或约束
通常有条件、适用范围和反例
能用于解释或推理

这类对象必须特别注意条件和边界。比如“F=ma”不能只抽成公式，要带上适用范围、惯性参考系、合外力、质量恒定等条件。

3.3 Procedure / Method Object：方法、步骤、实验操作节点

抽取对象：

过滤
蒸发结晶
用控制变量法设计实验
配制一定溶质质量分数的溶液
用伏安法测电阻
梯度下降算法

判定标准：

有步骤
有输入输出
有工具或材料
有操作条件
可以被执行或评价

适合 AI Runtime，因为它能绑定工具、实验、代码或仿真。

3.4 Representation Object：表征、模型、图、公式、符号系统节点

抽取对象：

化学方程式
电路图
电场线
函数图像
粒子模型
生态金字塔
s-t 图像
v-t 图像

判定标准：

它本身是学习目标
学生需要学会读、画、解释或转换它
它不是单纯图片资源，而是一种知识表征

这里要区分：教材里的某张图片通常是 evidence 或 realization；但“电场线”作为一种表征方式，应该是 Knowledge Object。AI-NKS 文档也提醒，多模态资源可以作为文本、公式、图示、视频、代码、仿真等存在，但资源应属于 Realization 或 Evidence，不应和语义核心混为一谈。

3.5 Skill Object：技能节点

抽取对象：

根据化学方程式进行简单计算
识别变量之间的函数关系
解释实验现象
用图像判断运动状态
区分事实与推论

判定标准：

它不是一个概念，而是一种可表现、可评价的能力
常常对应课标行为动词
常常跨多个概念

技能节点非常重要，因为课标往往以“能……”“会……”“理解……并能……”表达。这里不能把能力目标全部压扁成概念节点。

3.6 Task Object：任务 / 题型 / 问题模式节点

抽取对象：

判断某混合物是否为溶液
解释蜡烛燃烧质量变化
根据图像求速度
根据实验现象判断是否发生化学变化
设计对照实验

判定标准：

它经常作为学习或评价任务出现
需要组合多个知识对象
可以绑定题型、rubric、常见错误

AI-NKS 文档中知识驱动评价要求每个评价任务绑定目标 Knowledge Object、学习目标、认知层级、评分标准、常见错误模式和反馈建议，而且评价不只是判断对错，还要诊断学习者在哪些知识对象或关系上有缺口。

所以高频考点更适合先变成 Task Object，而不是强行变成 Concept Object。

3.7 Misconception Object：误解节点

抽取对象：

质量守恒意味着任何情况下称量质量都不变
电场强度取决于试探电荷大小
速度大则加速度一定大
训练集准确率高就代表模型泛化好

判定标准：

学生经常犯
能被诊断
有对应补救路径
和正确概念存在 contradicts / remediate-by 关系

这类节点对 AI Tutor 特别关键，因为 Tutor 不只是解释概念，还要诊断误解。

4. 什么不应该被抽成知识节点

这里很重要。抽节点最容易犯的错不是漏抽，而是把所有东西都抽成节点。

4.1 不抽章节标题本身，除非它表达稳定知识对象
第一章 物质的变化和性质
第一节 认识化学
活动与探究
本节小结
复习与提高

这些通常是 source structure，不是 Knowledge Object。

但如果标题本身就是概念，比如“质量守恒定律”“电场强度”，可以抽。

4.2 不抽一次性例子，除非它是典型案例或任务模式
蔗糖放入水中
铁丝在氧气中燃烧
小车沿斜面下滑

通常是 evidence / example / realization，不是节点。

但如果它是课程反复使用的典型实验，可以抽成 Task 或 Experiment Object：

探究质量守恒定律的实验
探究影响滑动摩擦力大小的因素
4.3 不抽孤立名词

教材里出现一个词，不代表它是节点。比如“烧杯”“玻璃棒”“水”“空气”是否抽，取决于它在当前知识网络中的作用。

如果只是实验材料，进入 evidence properties 或 method input 即可；如果它是学习对象，比如“空气的组成”“水的净化”，再成为节点。

4.4 不抽纯文本块

一个段落、一个说明、一个页码、一个小节，不应该直接成为节点。AI-NKS 明确反对把构建过程简单变成文档切 chunk；它强调要把资源转化为可验证、可治理、可运行的 Knowledge Object，而不是把资料放入数据库或切成 chunk 后做向量检索。

4.5 不把“考点名称”直接当概念

例如：

“电学综合计算”
“图像题”
“实验探究题”
“选择题易错点”

这些大多是 Task / Assessment / Skill，不是 Concept。

5. 一个可执行的节点准入标准

我建议每个候选节点都过一个 7 问门槛。

1. Identity：它是否有稳定名称或可规范化别名？
2. Definition：它是否能给出短定义或清晰描述？
3. Evidence：它是否至少有一个教材、课标、专家资料或题目证据？
4. Relation：它是否能和其他对象形成至少一种有意义关系？
5. Reuse：它是否会在多个解释、题目、路径或场景中复用？
6. Pedagogy：它是否有学习价值、诊断价值或评价价值？
7. Runtime：AI Tutor 是否需要单独检索、引用或组合它？

建议规则：

满足 5 条以上：可以进入 canonical node
满足 3–4 条：进入 candidate / review
低于 3 条：保留为 evidence、tag、example、source_fragment 或 metadata

这样能防止两种极端：

过粗：一章一个节点，最后退化成 chunk RAG
过细：每个词一个节点，图谱巨大但不可教、不可用
6. 粒度应该怎么控
6.1 最小粒度：能独立回答一个学习问题

一个好的节点，应该能独立回答至少一个问题：

它是什么？
它为什么成立？
它怎么用？
它和什么容易混？
它有什么条件和边界？

例如：

“电场强度”可以独立回答，所以是节点。
“电场强度的方向”一般不是独立节点，更适合作为 semantic_core.conditions / key_claims。

但如果某个子内容在教学上非常重要、经常出错、经常被评价，也可以升级为节点：

“电场强度方向”如果在题型中高频出现，可以成为 Skill / Proposition / Misconception 相关节点。
6.2 最大粒度：不要超过一个稳定知识对象

如果一个节点内部已经包含多个概念、多个技能、多个任务，就太粗。

例如：

“溶液”是合适节点。
“溶液的形成、组成和质量分数计算”太粗。

应该拆成：

Concept:
- 溶液
- 溶质
- 溶剂
- 饱和溶液
- 溶质质量分数

Process:
- 溶解

Skill:
- 计算溶质质量分数

Task:
- 判断某混合物是否为溶液
6.3 节点粒度不是一种，而是多粒度共存

不要试图把所有节点都变成“概念”。这会把教育知识图谱做歪。AI-NKS 文档明确把粒度研究作为关键问题：知识对象到底按概念、命题、技能、任务还是误解切分，会影响检索质量、学习路径和 AI Tutor 效果。

因此最合理的结构是：

Concept Object：是什么
Proposition / Rule Object：什么规律成立
Procedure / Method Object：怎么做
Representation Object：如何表示
Skill Object：能做什么
Task Object：如何评价 / 应用
Misconception Object：容易错在哪里
7. 如何保证知识完整性

“完整性”不是“抽得越多越完整”。完整性应该是四种覆盖。

7.1 课标覆盖

建立矩阵：

课程标准条目 × Knowledge Object

每条课标至少映射到：

核心概念
核心关系
学习目标
评价任务
必要前置知识

如果某条课标没有对象支撑，说明漏抽。

7.2 教材覆盖

建立矩阵：

教材 lesson / chunk × evidence × node

检查：

每个核心段落是否有 evidence
每个核心 evidence 是否支撑至少一个对象或关系
每个对象是否能追溯到教材位置
每个重要图、表、公式是否被纳入 evidence 或 representation

这里要注意：不是所有教材句子都必须生成节点；但核心知识表达必须被 evidence anchoring。

7.3 类型覆盖

每个单元不能只有概念节点，还应该检查是否覆盖：

Concept
Proposition / Rule
Procedure / Method
Representation
Skill
Task
Misconception

比如初中化学某一节如果只有“溶液、溶质、溶剂”几个概念，却没有“判断溶液”“区分悬浊液和溶液”“把所有混合物都当溶液的误解”，那么对教学来说仍然不完整。

7.4 关系覆盖

知识不是节点列表，而是网络。AI-NKS 文档强调 Knowledge Network 要表达语义关系、学习关系、证据关系、应用关系和演化关系；网络不是取消课程顺序，而是让课程顺序成为网络上的一种可生成路径。

所以每个核心节点至少应该有：

1 个上位或组成关系
1 个前置或后续关系
1 个应用或任务关系
1 个证据关系

如果大量节点孤立，说明“知识点抽取”成功了，但“知识网络构建”失败了。

8. 如何保证知识点准确性

准确性要靠流水线，不靠 prompt。

AI-NKS 文档给出的构建流程是：

Source Ingestion
→ Segmentation and Evidence Anchoring
→ LLM-Assisted Extraction
→ Knowledge Object Generation
→ Schema Validation
→ Ontology Alignment
→ Expert Review
→ Publication
→ Runtime Use
→ Feedback and Evolution

这说明抽取不是模型一次输出就结束，而是一个验证、对齐、审核、发布和演化的过程。

我建议 OKM 采用五道质量门。

8.1 Evidence Gate：没有证据，不进正式库

每个节点至少要有：

source_id
anchor_ref
page / paragraph / line
evidence excerpt
confidence

没有证据的内容可以进入 candidate，不能进入 active。

8.2 Schema Gate：结构不完整，不进正式库

检查：

是否有 name
是否有 kind
是否有 definition
是否有 domain
是否有 source_refs
关系 type 是否合法
source_refs 是否真实存在

AI-NKS 文档也提出 Schema Validation Gate：对象生成后要验证必填字段、ID 唯一性、关系类型、前置知识、版本格式、来源证据和教学属性。

8.3 Ontology Alignment Gate：相似概念不能乱合并

这是最容易出错的地方。文档也强调本体对齐是关键难点，系统需要判断不同来源中的概念是相同、相近、上下位还是冲突，并且对齐结果不应只有 same-as，还应包括 exact-match、close-match、broader-than、narrower-than、related-but-distinct、conflict、uncertain。

例如：

“速度变化率” 与 “加速度”：可能 exact-match 或 definition-level equivalent
“质量” 与 “重量”：related-but-distinct，不能合并
“化学变化” 与 “物理变化”：contrasts / related，不是 same_as
“溶解” 与 “溶化”：初中化学中必须区分
8.4 Expert Review Gate：核心对象必须人工审核

AI-NKS 文档明确说，高质量 AI-NKS 必须有人类专家参与，审核重点包括语义核心、关系、学习目标、常见误解、评价任务、来源证据和对齐关系。

建议分层审核：

核心节点：专家必审
高频考点节点：教师必审
低频支撑节点：抽样审核
自动生成正文：引用和 unsupported claims 检查
8.5 Runtime Feedback Gate：使用中继续修正

知识对象不是一次性完成。AI-NKS 文档也提到，学习者提问、AI Tutor 回答错误、教师修改、学习评价结果、新论文或新教材、运行时工具输出都可以进入反馈演化队列。

所以准确性不是静态指标，而是持续治理。

9. 一个实际可用的抽取策略

我建议采用 “先骨架、再证据、再扩展” 的三阶段方法。

阶段一：从课标和专家框架生成“目标骨架”

先不要让模型自由从教材里抽所有名词。先建立：

curriculum_outcomes
domain_concepts_seed
relation_type_policy
node_type_policy
grade_boundary

输出一个目标表：

must_have_objects
should_have_objects
optional_objects
forbidden_or_metadata_only_terms

这一步解决“完整性边界”。

阶段二：从教材抽“证据支撑的候选对象”

模型只处理当前 lesson/chunk，抽：

候选节点
候选关系
证据
定义
条件
例子
误解
任务

但模型输出只进入 staging，不直接 active。AI-NKS 文档也强调，LLM 可以辅助抽取概念、定义、公式、条件、关系、例题、学习目标、常见误解、评价任务，但不能直接进入正式知识库，必须保留来源、置信度和待审核状态。

阶段三：用课标 / 考点 / 专家规则做归并和补全

处理：

同义归并
上下位关系
漏抽核心对象
误抽目录标题
技能 / 任务 / 误解升级
证据不足降级

最终进入 canonical graph。

10. 对 OKM 的具体规则建议

可以直接在项目里写成 docs/node-extraction-policy.md 或 schemas/extraction-policy.yaml。

10.1 节点类型白名单
node_types:
  concept:
    description: "可定义、可复用的概念"
  proposition:
    description: "稳定命题、定理、规律、结论"
  procedure:
    description: "可执行方法、实验步骤、算法"
  representation:
    description: "公式、图像、模型、符号系统等表征方式"
  skill:
    description: "可表现、可评价的能力"
  task:
    description: "评价任务、问题模式、应用任务"
  misconception:
    description: "常见误解或错误规则"

当前 world-v1.2 里只有九类 kind，暂时可以这样映射：

concept → concept
proposition / rule → rule
procedure / method → method
representation → representation
skill → method 或 properties.object_type = skill
task → resource 或 properties.object_type = task
misconception → concept 或 properties.object_type = misconception

长期可以扩展上层 object_type，不要强行把所有东西塞进 kind。

10.2 节点准入规则
node_admission:
  required:
    - stable_name
    - short_definition_or_description
    - at_least_one_evidence
    - object_type
  should_have:
    - relation_to_existing_object
    - curriculum_mapping
    - pedagogical_role
    - reusable_context
  reject_if:
    - pure_chapter_heading
    - pure_page_fragment
    - decorative_label
    - one_off_example_without_reuse
    - no_evidence
    - duplicate_alias_of_existing_object
10.3 粒度规则
granularity:
  too_coarse_if:
    - contains_multiple_definitions
    - contains_multiple_unrelated_skills
    - maps_to_many_curriculum_outcomes_without_internal_structure
    - cannot_be_explained_in_one_unit_page
  too_fine_if:
    - cannot_be_defined_independently
    - only_appears_as_phrase_modifier
    - has_no_relation_except_parent_text
    - not_reused_in_any_task_or_explanation
  split_when:
    - definition_and_application_both_large
    - concept_and_skill_mixed
    - rule_and_example_mixed
    - misconception_has_distinct_diagnostic_value
  merge_when:
    - same_definition
    - same_curriculum_role
    - aliases_only
    - no_distinct_pedagogical_or_runtime_use
11. 一个例子：抽“质量守恒定律”这一节

不要只抽：

质量守恒定律

也不要抽一堆散词：

质量
反应
烧杯
天平
白磷
气球
实验
观察
思考

更合理的是：

Concept:
- 质量
- 化学反应
- 反应物
- 生成物
- 封闭体系

Rule / Proposition:
- 质量守恒定律

Procedure / Task:
- 验证质量守恒定律的实验
- 用质量守恒定律解释反应前后质量变化

Representation:
- 化学方程式，若本节已正式涉及
- 反应前后质量关系表达式

Misconception:
- 生成气体逸出导致称量质量变小，就说明质量不守恒
- 物质消失意味着质量消失

Relations:
- 质量守恒定律 depends_on 化学反应
- 质量守恒定律 applies_to 封闭体系中的化学反应
- 化学反应 produces 生成物
- 反应物 part_of 化学反应描述
- 误解 contradicts 质量守恒定律

这样抽出来的不是“教材目录图谱”，而是可以支撑解释、诊断、路径和评价的知识网络。

12. 最终答案：到底参考谁？

我的建议是：

课标是边界
教材是证据
考点是评价
目录是线索
专家本体是结构
学习数据是反馈
AI Runtime 是使用场景

更具体地说：

来源	主要作用	不应该承担的作用
课标	范围、目标、能力要求、学段边界	不直接等于节点列表
教材	证据、表达、例子、顺序、图表公式	不直接决定对象边界
教材目录	切分、导航、学习路径初稿	不直接当知识对象
考点 / 题库	任务、评价、权重、常见错误	不决定知识是否存在
学科本体	类型、上下位、关系、归一化	不能脱离教育场景
教师专家	审核、边界判断、误解确认	不应手工维护全部低价值节点
学习者问题	发现缺口、误解、补救路径	不应直接改写知识真理

所以，知识节点的最终判定标准不是“它来自哪里”，而是“它在知识体系中扮演什么角色”。

13. 我会给 OKM 定一个最简判定公式

可以写成：

Knowledge Node =
  Stable Knowledge Identity
  + Evidence Anchor
  + Relation Potential
  + Pedagogical Use
  + Runtime Reusability

只有同时具备这些特征，才进入正式节点。

而其他内容分别放到：

source_fragment：原文片段
evidence：证据
media：图片 / 表格 / 公式资源
tag：检索标签
domain_profile：课标、学段、学习目标、考点权重
node_body：可读解释
task / assessment：题目和评价
review_queue：不确定候选
14. 一句话总结

课标、考点、教材目录都不能单独决定“什么是知识节点”。新的知识体系应该以 Knowledge Object 为基本单位：凡是能被稳定定义、证据支撑、关系连接、教学使用、AI 调用和持续治理的东西，才抽成节点；否则就应该降级为证据、例子、标签、任务、画像或教材结构。
