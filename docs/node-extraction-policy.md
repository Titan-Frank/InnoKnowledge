# 知识节点准入政策

本文固定当前阶段从教材、课标、考点、目录、专家知识和学习数据中抽取知识节点的判断规则。

这份政策解决的问题不是“模型应该多抽还是少抽”，而是“什么内容有资格成为可治理的知识对象”。它服务于抽取提示词、暂存质量检查、人工复核和后续小范围评测。

## 一、核心结论

知识节点不是文本切块，也不是把教材目录、课标条目或考点名称原样搬进图谱。

当前阶段的准入定义是：

> 知识节点 = 稳定知识身份 + 证据锚点 + 关系潜力 + 教学用途 + 运行时可复用性。

也就是说，一个候选节点至少应该满足五个条件：

1. 它有相对稳定的名称和含义，可以在不同材料中被再次识别。
2. 它能回到教材、图片、表格、公式、实验、课标或人工审核证据。
3. 它有和其他知识对象发生关系的潜力，而不是孤立的一次性标题。
4. 它能支持解释、教学、诊断、练习或学习路径组织。
5. 它未来可以被检索、组合、生成或反馈系统复用。

## 二、来源分工

不同来源在新知识体系中承担不同角色，不能互相替代。

| 来源 | 主要作用 | 不应该承担的作用 |
|---|---|---|
| 学科 | 提供领域视角、解释框架和学习路径条件 | 不作为唯一知识组织方式 |
| 课标 | 提供范围、目标、能力要求和学段边界 | 不直接等于节点列表 |
| 教材 | 提供证据、表达、例子、顺序、图片、表格、公式 | 不直接决定知识对象边界 |
| 教材目录 | 提供切分、导航和学习顺序线索 | 不直接当知识节点 |
| 考点 / 题库 | 提供任务、评价、权重和常见错误 | 不决定知识是否存在 |
| 学科本体 | 提供类型、上下位、归一化和关系约束 | 不能脱离教育场景 |
| 教师专家 | 提供审核、边界判断和误解确认 | 不应手工维护全部低价值节点 |
| 学习者数据 | 发现误解、缺口和补救路径 | 不直接改写知识事实 |
| AI Runtime | 提供检索、组合、生成、诊断和反馈场景 | 不反向破坏底层 schema |

## 三、明确排除

以下内容不能因为在教材或课标中出现，就自动成为正式知识节点。

1. 知识节点不等于课标条目。
2. 知识节点不等于教材目录。
3. 知识节点不等于考点名称。
4. 知识节点不等于文本切块。
5. 知识节点不等于复习题、栏目名、章节编号、学习活动标题或页内导航标题。

这些内容可以作为证据、边界、评价任务、导航线索或人工复核线索，但不能直接进入正式 active 节点。

## 四、准入检查清单

抽取和复核候选节点时，先按下面的问题判断。

| 检查项 | 应通过的判断 |
|---|---|
| 稳定身份 | 名称和定义是否能脱离当前句子存在，是否能在其他材料中再次识别 |
| 证据锚点 | 是否有教材、图表、公式、实验、课标或人工审核证据支撑 |
| 关系潜力 | 是否能形成上下位、组成、前置、因果、表征、应用、依赖等关系 |
| 教学用途 | 是否能用于解释、学习目标、误解诊断、练习或补救 |
| 运行复用 | 是否适合未来被对象级检索、语义规划、生成系统或学习反馈复用 |

只满足“出现过一次”或“标题看起来重要”的候选，不应该直接成为正式节点。

## 五、七类教育对象只作为检查清单

当前工程不把七类教育对象写入 `world_nodes.kind`，也不新增正式 `object_type` 字段。

`world_nodes.kind` 仍然只允许当前九类顶层类型：

```text
entity / concept / property / process / event / method / rule / representation / resource
```

七类教育对象只作为节点准入和评测时的观察清单：

1. 概念类对象：是否表达一个可定义的概念。
2. 命题或规则类对象：是否表达一个可判断、可解释、可应用的结论。
3. 过程或方法类对象：是否表达步骤、方法、实验或操作。
4. 表征类对象：是否表达公式、图示、模型、方程式、图像或符号系统。
5. 技能类对象：是否表达可训练、可迁移的学习能力。
6. 任务类对象：是否表达评价、练习、问题解决或应用情境。
7. 误解类对象：是否表达稳定、可诊断、可干预的常见错误。

这七类用于帮助人工和模型判断粒度，不作为当前数据库 schema 和 API 契约。

## 六、当前工程落点

当前工程采用保守落地方式：

1. 不修改 `world_nodes.kind`。
2. 不新增正式 `object_type` 字段。
3. `world_nodes.properties.semantic_core` 用来承载稳定语义核心。
4. `world_domain_profiles.properties.pedagogical_profile` 用来承载教学画像。
5. `staging-quality` 对明显违反准入原则的候选先给 warning。
6. 只有无证据、无定义、无画像、无卡片、无提及等结构性问题才继续作为 blocking error。

政策口径是：

> No evidence, no active node.

没有证据的候选可以进入候选池或人工复核，但不能进入正式 active canonical node。当前项目的原则仍然是：每个知识结论都应能回到证据。

## 七、典型 warning

暂存质量检查可以提示但不直接拦截下面这些情况：

1. 候选节点名称像章节、栏目、复习题、练习题或活动标题。
2. 候选节点名称像考点、题型或评价标签。
3. 候选节点只有孤立名词，没有定义、语义核心或关系。
4. 候选节点没有任何入边或出边，关系潜力不足。
5. 候选节点只来自目录线索，没有正文、图片、表格、公式或实验依据。

这些 warning 的目标不是让机器一次判死，而是把低质量候选推给复核、合并或降级流程。

## 八、与后续工作的关系

这份政策应该接入三处：

1. 抽取提示词：要求模型先证据、后节点，并按准入清单解释候选边界。
2. JSON 输出和归一化：继续保留 `semantic_core` 和 `pedagogical_profile`，不引入七类正式节点类型。
3. 暂存质量检查：把无证据、纯目录、孤立名词、考点误当概念等问题转成可观测 warning。

后续如果确实需要表达更细教学角色，应优先在教学画像中增加可选字段，而不是扩大顶层节点类型。
